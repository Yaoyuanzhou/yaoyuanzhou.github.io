一句话总结

GFlowGR 将生成式推荐（GR）形式化为多步序列生成问题，用 GFlowNet 的 flow-matching 机制提供 Token 级别的监督信号（SFT/DPO/GRPO 只做 Item 级别），通过轨迹采样器（4 种策略）+ 多信号奖励模型（交互信号 + CM 预估 + Token 相似度）+ DB/TB 双 Loss 变体，在淘宝全量广告 1 亿+用户 A/B 测试中实现总营收 +0.43%、非首页搜索 +1.11%，训练成本仅为 SFT 的 2.1×。

📄 原文：https://arxiv.org/abs/2506.16114

🔗 关键词：GFlowNet · 生成式推荐 · Token 级监督 · 轨迹采样 · 多信号奖励 · DB/TB Loss

三句话核心贡献：
① 将 GFlowNet 引入 GR 微调，实现 Token 级别监督——SFT/DPO/GRPO 只能做 Item 级，GFlowNet 通过 flow-matching 对每个生成 token 给予奖励信号；
② 提出完整 GFlowNet 微调框架：4 种轨迹采样策略（含 CM-based Curriculum）+ 3 信号奖励模型 + DB/TB 双 Loss；
③ 淘宝全量广告 A/B 验证：1 亿+用户，总营收 +0.43%，非首页搜索 +1.11%，训练成本仅为 SFT 的 2.1×。

1. 背景与动机

生成式推荐（GR）的核心范式

生成式推荐将推荐任务建模为自回归序列生成：给定用户历史交互序列 $[i_1, i_2, \ldots, i_t]$，模型自回归地生成下一个 item 的 token 序列 $[s_1, s_2, \ldots, s_L]$，其中 $s_l$ 是第 $l$ 级 Semantic ID token。整个生成的联合概率为：

$$P(s_{1:L} \mid u) = \prod_{l=1}^{L} P(s_l \mid s_{1:l-1}, u)$$

现有微调方法的局限

SFT（监督微调）

  • 仅模仿 ground truth token 序列
  • 无法感知"生成得好不好"——没有价值信号
  • 容易学到次优的 token 生成路径

DPO / GRPO（偏好对齐）

  • 仅对整个 item 序列打分（Item 级别）
  • 无法区分「第 1 步好+第 2 步差」vs「第 1 步差+第 2 步好」
  • Token 级别的生成质量无法被精细优化
核心矛盾：现有微调方法都只能做 Item 级别的监督——要么模仿（SFT），要么整体打分（DPO/GRPO）。但在生成式推荐中，每个 token 的生成质量直接影响最终推荐效果。能否给每一步 token 生成都提供精细的奖励信号？

GFlowNet 的本质：Generative Flow Networks（GFlowNet）的核心目标是让生成概率正比于奖励：$P(\tau) \propto R(s_L)$。它通过在生成轨迹上的 flow-matching 机制，将终端奖励 $R(s_L)$ 反向传播到每一步 token 生成——这正是 Token 级监督的自然载体。

GFlowNet 为什么适合 GR：GR 的自回归生成天然是一个 DAG（有向无环图），每个 token 是图中的一个节点。GFlowNet 的 flow 守恒约束恰好可以作用于每个 token 生成步骤，将终端奖励信号分配到每一步的生成决策中。

2. 方法详解

2.1 整体框架

GFlowGR 的核心思想：将 GR 的 token 序列生成视为 GFlowNet 的轨迹 $\tau = s_0 \to s_1 \to \ldots \to s_L$，其中 $s_l$ 是第 $l$ 个 token。通过 GFlowNet 的 flow-matching 约束，让每个 token 的生成概率 $P(s_l \mid s_{1:l-1})$ 与最终的奖励 $R(s_L)$ 相关联。

2.2 轨迹采样器（Trajectory Sampler）

GFlowGR 设计了 4 种轨迹采样策略，逐步提升采样质量：

策略方法特点
Interaction Log从用户真实交互日志采样保真度高，但覆盖有限（仅正面样本）
Random随机采样 token 序列覆盖广，但质量低，大量无效轨迹
CM-based Curriculum用 Click Model（CM）筛选高潜力轨迹，按 CM 分数分批次训练课程学习策略：先易后难，平衡探索与利用
On-policy用当前模型生成轨迹在线策略，与模型当前能力匹配，但训练不稳定
💡 举例：CM-based Curriculum 采样

假设我们有 10 万条历史交互轨迹，每条轨迹对应用户点击了某个商品。

Batch 1（低 CM 分）：先从 CM 预估分最低的 30% 轨迹中采样——这些"容易区分"的样本帮助模型快速建立 token 生成与奖励的基本关联。

Batch 2（中等 CM 分）：再从 CM 预估分中等的 40% 轨迹中采样——模型学习更复杂的 token-奖励映射。

Batch 3（高 CM 分）：最后从 CM 预估分最高的 30% 轨迹中采样——"困难"样本迫使模型精调每个 token 的选择。

这种课程学习策略（Curriculum Learning）让模型从"容易分辨的 token"逐步过渡到"难以分辨的 token"，避免了随机采样中大量低质量轨迹带来的噪声。

2.3 多信号奖励模型（Multi-Signal Reward Model）

GFlowGR 的奖励模型融合三种信号：

$$R(s_L) = r_a + \alpha \cdot r_c + \beta \cdot r_{\text{sim}}$$
符号说明
  • $r_a$：交互信号——用户是否点击/购买（二值：0 或 1）
  • $r_c$：CM 预估分——Click Model 对 item 吸引力的预估（连续值 [0, 1]）
  • $r_{\text{sim}}$：Token 相似度——生成 token 序列与目标 item 真实 token 序列的相似度
  • $\alpha, \beta$：平衡系数
三种信号的各自作用：$r_a$ 提供真实的交互反馈（最强信号但稀疏）；$r_c$ 提供稠密的预估信号（数据多但可能有偏差）；$r_{\text{sim}}$ 提供格式约束（确保生成的 token 是有效 SID 且与目标 item 语义相近）。

2.4 DB/TB 双 Loss 变体

GFlowGR 支持两种 GFlowNet 训练损失：

Detailed Balance（DB）Loss — 步骤级

$$\mathcal{L}_{DB} = \sum_{l=1}^{L} \left( \log F(s_{l-1} \to s_l) - \log \hat{F}(s_{l-1} \to s_l) \right)^2$$
符号说明
  • $F(s_{l-1} \to s_l)$：从状态 $s_{l-1}$ 转移到 $s_l$ 的 flow（由网络预测）
  • $\hat{F}(s_{l-1} \to s_l)$：满足 Detailed Balance 约束的目标 flow 值
  • DB 在每个 token 步骤计算 loss，粒度最细，适合大规模并行训练

Trajectory Balance（TB）Loss — 轨迹级

$$\mathcal{L}_{TB} = \left( \log Z \prod_{l=1}^{L} P_F(s_l \mid s_{l-1}) - \log R(s_L) \right)^2$$
符号说明
  • $Z$：从初始状态的总 flow（可学习参数或固定值）
  • $P_F(s_l \mid s_{l-1})$：前向策略（forward policy），即模型当前输出 token 的概率
  • $R(s_L)$：终态奖励
  • TB 在完整轨迹上计算 loss，方差更小，但训练效率低于 DB
💡 举例：DB vs TB 的区别

假设一条 3-token 轨迹 $(s_1, s_2, s_3)$ 最终奖励 $R=0.8$。

TB Loss：只看整条轨迹——"模型认为这条轨迹的总概率 × Z，与 0.8 的偏差是多少？"一条轨迹一个 loss 值。

DB Loss：看每一步——"模型认为 $s_0 \to s_1$ 的 flow 应该是多少？$s_1 \to s_2$ 呢？$s_2 \to s_3$ 呢？"每步都要满足 flow 守恒，一共 3 个 loss 项。

DB 粒度更细，每步都有监督信号，适合并行训练（每步 loss 可独立计算）。TB 粒度粗但方差更小，适合对整条轨迹有清晰偏好的场景。

2.5 完整训练流程

  1. 1
    SFT 预训练：用标准 SFT 对 GR 模型进行基础训练，使其学会基本的 token 生成模式
  2. 2
    轨迹采样：用 4 种采样策略（Interaction Log → Random → CM-based Curriculum → On-policy）生成多样化轨迹
  3. 3
    奖励计算：对每条轨迹计算多信号奖励 $R(s_L) = r_a + \alpha r_c + \beta r_{sim}$
  4. 4
    GFlowNet 微调：用 DB Loss 或 TB Loss 将奖励信号反向传播到每个 token 步骤，更新模型参数
  5. 5
    迭代：重复步骤 2-4，逐步提升 token 级别生成质量

3. 实验结果

离线实验（淘宝工业数据集）

在 1 亿+用户的淘宝广告数据集上，GFlowGR 在多个指标上全面超越 SFT baseline：

SFT (baseline)0.72400.68320.21430.1521

消融实验

在线 A/B 测试（淘宝全量广告，1 亿+用户）

  • 总营收提升：+0.43%
  • 非首页搜索场景营收提升：+1.11%
  • CTR 提升：+0.38%
  • CVR 提升：+0.52%
  • 训练成本：SFT 的 2.1×

DB vs TB 对比

  • DB Loss：AUC 略高，因为步骤级监督粒度更细，适用于 item 数多、token 序列长的场景
  • TB Loss：训练更稳定，方差更小，适用于对整条轨迹有明确偏好的场景

4. 个人理解与启发

核心亮点

  • Token 级监督是 GR 的必然方向：SFT 只模仿、DPO 只比大小，都太粗糙。GFlowNet 提供了一套优雅的 Token 级监督框架——这可能是生成式推荐从"能跑"到"跑得好"的关键一步。
  • GFlowNet 与 GR 的天然契合：GR 的自回归生成天然是有向无环图（每个 token 是状态节点），正是 GFlowNet 的标准应用场景。Flow-matching 约束恰好可以分解到每步 token 生成。
  • CM-based Curriculum 是关键工程创新：随机采样产生大量噪声，on-policy 采样不稳定。用 Click Model 做课程学习——先易后难、逐步提升——是一个实用的工程方案。
  • 多信号奖励的设计哲学：真实交互（$r_a$）最可靠但稀疏，预估信号（$r_c$）密集但有偏，格式信号（$r_{\text{sim}}$）保证合理性。三者互补，构成完整的奖励函数。

潜在不足

  • 训练成本是 SFT 的 2.1×，对大规模系统仍有开销压力
  • 奖励模型的三个系数 $\alpha, \beta$ 需要按场景调参
  • On-policy 采样策略在大规模训练中可能不稳定
  • 论文未讨论 GFlowNet 微调后在 serving 阶段的推理效率

对我的启发

GFlowGR 提供了一个很好的思路：将生成式推荐的 token 生成过程视为 DAG 上的轨迹采样，用 flow-matching 约束实现 Token 级精细优化。这个视角可以推广到其他序列生成场景（如多轮对话推荐、多步推理推荐），其中每一步生成都需要独立的、精细的监督信号。

此外，CM-based Curriculum 的课程学习策略在推荐系统微调中非常实用——与其用全部数据无差别训练，不如按样本难度分层、从易到难地逐步提升模型能力。这种方法在其他 RL-based 微调方案（DPO/GRPO）中也可以借鉴。
